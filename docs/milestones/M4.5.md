# M4.5 — Tested where it runs

## Done when

> **The client's prediction loop is tested where it actually runs, and the copies that can
> silently drift from it are gone.**

This milestone was opened as "some files are becoming too large". A codebase audit
(`docs/research/codebase-audit-m5.md`) and a survey of released engine source
(`docs/research/round-type-architecture.md`) both say that is the wrong target, and the
scope changed to follow the evidence rather than the impression:

- The large files rank **#14–#16 at Low risk** in the audit's own backlog. `tuning.ts` is
  "not tangled, cosmetic". `scene.ts` has **zero test coverage**, so splitting it would be
  unguarded surgery on a problem nobody has. `CharacterController` is smaller than the shipped
  controllers the engines never cut, and the only seams those engines make are the
  collide-and-slide kernel and the saved-move surface — and this project already has the second.
- What ranks **#1, High risk at XS cost**, is something the original framing never mentioned:
  `apps/client`'s predict/reconcile loop has no seam, so `predictionRegression.harness.test.ts`
  tests a **hand-maintained copy** of it. Its own header says so. There are three implementations
  of the reconciliation correction gate and **two have already drifted from production** — one
  still asserts `positionError > 0.2`, a threshold **ADR 0026 retired**.

**Selection criterion:** a file earns a change only when it has two or more concerns that change
independently, evidenced by the audit — never because of its line count alone. Note that
`apps/server/src/index.ts` passes that test comfortably and was still initially excluded for the
wrong reason (see below): a 620-line function holding the Track fetch, the socket lifecycle, the
Lobby, the input queue and the tick loop is the criterion's central case, not its exception. **Every ticket moves code; none changes behaviour.** A
diff that changes logic belongs in a different ticket.

**Explicitly deferred to M5, not skipped:** anything the Round-type seam will reshape. M4.5 splits
by concern; M5 splits by authority. Untangling `RapierSimulation`'s Race rules now would mean
guessing at an answer M5 is about to produce, and paying for two refactors to get one.

## Checklist

### The spine — the prediction loop
- [x] Both test copies of the reconciliation correction gate call the real `needsCorrection`;
      the stale `positionError > 0.2` and the missing `finishTick` term die with them
- [x] The client's predict/reconcile loop is extracted so the regression harness drives
      **production code** rather than a port of it
- [x] `predictionRegression` still passes, with its numbers unchanged — the harness is measuring
      the same thing, just no longer measuring a replica. (One documented exception: three
      "60 fps render cap" assertions under the harshest "bad" network profile moved because the
      old ported `reconcile` diverged from production's own capsule-offset reset condition — a
      real, pre-existing production gap the replica wasn't faithful enough to catch. See ticket
      02's own notes and the affected tests' comments in `predictionRegression.harness.test.ts`.)

### Housekeeping
- [x] One `isDownMotionState`; the other five copies deleted
- [x] Things that belong in `packages/shared` live there — `qualificationPlacement`, `StoredTrack`
- [x] Dead code deleted: the renderer accessors on `RapierSimulation` nothing calls, their clone
      helpers, and the test fixture exported from shared's public index
- [x] The Track builder's Time Limit bounds come from the shared constants, not a third copy in HTML
- [x] `selectTrack` has tests, and shares the reload path it currently duplicates
- [x] HUD text comes out of the frame loop as a pure function

### Structure
- [ ] `apps/client/src` is organised by kind instead of thirty-six files at the root, and the
      `game.ts` / `game/` collision — which currently names the React component after the module

      split by concern into `match/`, `net/` and `track/` — folders, not seven loose modules —

### Verification
- [x] Full suite green with **no changed assertions** — import paths and fixture construction may
      change; a modified `expect` is evidence of changed behaviour and must be justified
- [ ] One live two-browser playthrough at the end of the milestone, not per ticket

## Explicitly NOT in M4.5

Splitting `CharacterController` · splitting `scene.ts` (zero coverage — do not do this
opportunistically) · splitting `tuning.ts` (104 constants, no duplication, no dead entries, one
concern) · anything the Round-type seam reshapes · new features · "while I'm here" fixes, which
become their own tickets.

**Restructuring `apps/track-builder`** — eight files with an obvious layout and no reader
complaining; doing it for symmetry alone is churn.

*(`apps/server` was on this list and has been moved into scope as ticket 09. The reasoning was
wrong: it conflated "give the match loop a file of its own", which is safe and evidence-backed,
with "pick the seams inside the match loop", which is what M5 would have overwritten. Only the
second was ever the risk, and `startServer` is a 620-line function in the meantime.)*

These are recorded as decisions, not omissions, so they are not re-litigated every time someone
opens a thousand-line file.
