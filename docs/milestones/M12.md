# M12 — The Environment

## Done when

> **A Track author picks `day`, `sunset` or `night` in the builder, previews it
> there, and every Round on that Revision is drawn under that sky — a gradient
> dome, a cloud floor to fall into, drifting clouds, matching fog, light,
> reflections and real shadows — without the server knowing it exists.**

Every Round today runs in a flat navy void. Researched in
`docs/research/track-environment-sky-and-clouds.md`, settled with the user
(2026-09-16) and recorded as **ADR 0074**, with **Environment** added to
`CONTEXT.md`.

## Design

- An Environment is a named preset: three-free data in `packages/shared`,
  drawn by one `createEnvironment(scene, renderer, preset, options)` seam in a
  new `packages/render` that both the game and the Track builder import.
- Render-only by rule: never in `RoundRules`, never on the Snapshot, never read
  by the server or the shared step.
- The preset id lives on the Revision row (like `time_limit_ms`, ADR 0038); the
  author picks it in the builder; an unknown id falls back to `day`.
- Sky: a camera-following gradient dome. Under the Track: a cloud floor derived
  from the kill height (−8, unchanged), replacing the drawn kill plane. Clouds:
  instanced low-poly puffs that drift on the wall clock.
- Fog is linear, in the horizon colour. Lights, a PMREM environment map and the
  shadow direction all come from the preset's palette and sun.
- Neutral tone mapping in both apps; real shadow maps; a multisampled composer
  target.
- The builder previews the Environment behind a toggle; the lavender authoring
  view stays the default (ADR 0063).

## Not in this milestone

Distant backdrop scenery (research §4), a Lobby override of the Revision's
Environment, a per-Track kill height, other under-Track kinds (sea, lava),
height fog, moving the existing per-app texture duplicates into
`packages/render`.
