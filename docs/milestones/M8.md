# M8 — Asset-backed Modules

## Done when

> **Four Track pieces load from `assets/` — every Player sees and collides
> with the same authored geometry — instead of procedural boxes.**

M1–M7 built a game whose world is code: `M1_MODULES` flattens to oriented
boxes, and `createStage` draws those same boxes. It plays, but it can never
look like anything. Meanwhile `assets/` already holds four authored GLBs
(`platform_straight`, `ramp_45`, `stairs_4step`, `corner_lshape`), each with
a `role: collision` node and a `role: visual` node — placeholders today
(14–56 verts, untextured), but shaped exactly like the future.

**This milestone is the pipeline, not the pretty.** Settled in a grilling
session (2026-09): M8 makes the four placeholders playable through the full
client/server pipeline, so final beveled/textured visuals become a pure
content drop later that changes no code. Recorded as **ADR 0050**, with
**Asset** / **Collision mesh** / **Visual mesh** added to `CONTEXT.md`.

## Design

Grilled round by round; the full tree is in the session, the decisions in
ADR 0050. In short:

- One GLB per Module, `<moduleId>.glb`, `role` extras authoritative (the
  stray `collision: True` on visual nodes is ignored, then stripped).
- One shared GLB reader in `packages/shared` (no three.js there); server
  fetch from track-service (ADR 0050 as amended); both parse the same bytes.
- Collision is a Rapier trimesh verbatim from the collision node — statics
  only. Surfaces ride node extras (`node ?? Module ?? "default"`), unknown
  ids are a load error.
- Load-time validation in shared code: collision past footprint +
  `ASSET_FOOTPRINT_EPSILON` (0.02) fails everywhere identically; visuals
  past collision + `ASSET_VISUAL_WARN` (0.05) warn only. Node transforms
  are baked, never required identity.
- One pipe for bytes (ADR 0050 as amended): track-service serves GLBs from
  disk, floating revisions; match server fetches at boot, client at track
  load, builder at tab open — fetch-once-per-loader, with the documented
  mid-fetch-edit window.
- Asset Modules are a new Module kind alongside procedural ones; the track
  builder gets them through its own Assets tab (ticket 05).

## How this milestone is verified

M7's rule stands: every ticket carries its own live verification in its own
"Done when", and is not done without it. Ticket 04 holds the milestone-level
playtest (a real Match on asset Modules); tickets 01–03 hold unit/integration
proof each.

## Explicitly NOT in M8

Final beveled/textured visuals (a content drop, no code) · dynamic or
articulated asset parts — spinner arms and the like stay procedural until a
dynamic representation is designed · LODs · track-service as an art store
(versioned/fetchable art is a content-pipeline milestone) · pre-baked
collision JSON · new Modules or Tracks beyond the four · anything that
changes scoring, netcode, or Match structure.
