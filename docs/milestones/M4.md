# M4 — Match structure + the first Screens

## Done when

> **Two players meet in a lobby, race one Track against its clock to the Finish Zone, and see who
> qualified — then do it again on another Track.**

Design settled in a three-round grilling session (2026-09, Q1–Q18). Recorded as ADR 0038 (Time
Limit per Revision), ADR 0039 (Finish Zone entity), ADR 0040 (server-authoritative phase + lobby
transport). M4 is deliberately a single-Race slice: one Race Round per Match, but the Match state
machine is shaped as `rounds: [...]` from the start, so multi-Round advancement later is a rule
change, not a rewrite — the same slice logic as M2's "validated at 2, shaped for 12" (ADR 0011).

**Selection criterion:** nothing in M4 adds a movement, Surface, or Impact mechanic. The only new
replicated data is Match phase, the clock, and who qualified — everything a Character does inside a
Round is M1–M3.7 unchanged.

## Checklist

### Track data
- [ ] `Module` gains an optional Finish Zone trigger: detection-only, shaped like a Checkpoint's
      `trigger`, reusing the rotation-safe containment pipeline (ADR 0039)
- [ ] `tracks` gains per-Revision `timeLimitMs`; the `Segment[]` publish contract is unchanged;
      pre-M4 Revisions (including the M1 seed) backfill a 180 s default (ADR 0038)
- [ ] Track builder edits both per Draft (Finish Zone placement + Time Limit number); the lobby reads
      the Time Limit, never writes it
- [ ] Seed content gets an authored Finish Zone so old Tracks are raceable

### Match authority (server)
- [ ] Phase machine LOBBY → COUNTDOWN → RUNNING → ROUND_END → RESULTS, server-owned from COUNTDOWN
      on (ADR 0040)
- [ ] COUNTDOWN is 3 s from the server Tick: Characters spawned (join order → spawn offset, the
      `playgroundSpawn` pattern), input locked, cameras live
- [ ] Finish detection server-side (capsule centre in the Finish Zone → record `finishTick`, lock that
      Character's input, leave them spectating in the zone)
- [ ] Clock enforced server-side from `timeLimitMs`; the Round ends early when all connected
      Characters are qualified
- [ ] Disconnect removes the Character and records DNF; no mid-round rejoin
- [ ] Snapshot carries `phase + timeLeftMs + qualified {characterId: finishTick}`; lobby messages
      (join / ready / select / start) travel the existing WS — no new service

### Screens (React, ADR 0008)
- [ ] `apps/client` entry flips to `<App>` with router; the game module stays code-split behind a
      dynamic `import()`; the `<GameCanvas>` boundary (`config in, onMatchEnd/onExit out`) holds
- [ ] Routes: main menu → lobby (nickname label, ready toggles, Track dropdown from the
      track-service listing, host = first joiner starts when all ready) → game → results
- [ ] Results rank Qualified by finish time and DNF by checkpoint progress, show falls per player;
      both players return to the lobby and the host may start another Round on another Track; no
      auto-rematch timer

### HUD (plain DOM, ADR 0008)
- [ ] Round timer from server time, Qualified `n/2`, personal banner (`Qualified #n` / `Eliminated`);
      existing dash/checkpoint elements unchanged
- [ ] No live standings / leadership indicator (deferred)

### Verification
- [ ] Live 2-browser playthrough as in M2/M3.7: lobby → countdown → race → one qualifier waits in
      the zone while the other finishes → results → back to lobby → a second Round on another
      Track; plus a Time Limit expiry with a DNF, plus a disconnect-mid-Round DNF. Not just vitest.

## Explicitly NOT in M4

Multi-Round advancement and Qualification carry-over · live standings or "who leads" · mid-round
rejoin / reconnect-into-running · auto-rematch timer · matchmaking, instance orchestration,
shareable lobby links · accounts / registration · Bet screen and spectator betting · Power-ups,
Item Box, Grab · Survival / Collect / Team Round types · Skyfall · generator placement of Finish
Zones and Time Limits (authored only).
