# M13 — Smooth on a weaker PC

## Done when

> **On the base race, the frame time and the server tick are measured before
> and after. Entering a Match downloads and parses only the Track's Assets.
> A player on a weaker PC can pick a graphics quality level that keeps the game
> within the frame budget (checked on the dev Mac with 4× CPU throttling). Whether physics needs distance activation is decided
> from those numbers, not from intuition.**

Researched in `docs/research/gameplay-performance-culling-and-asset-loading.md`
(2026-09-16). Settled with the user (2026-09-17; the note's "Decisions" section
has the full list):

- measure first, so every later change has a before/after,
- physics distance activation only if the numbers ask for it,
- graphics quality is chosen by the player, never switched automatically; its
  lowest level turns shadows off (**ADR 0079**),
- the camera's far plane follows the fog,
- no weaker PC is measured, since the user has none. The dev Mac with 4× CPU throttling stands in
  for a weak CPU; a weak GPU stays unmeasured.

## Design

- **Measure in two places.**
  - The client: a dev overlay, plain DOM (ADR 0008). It shows frame-time
    percentiles, `renderer.info`, sim steps and replayed ticks per frame.
  - The simulation: a headless benchmark of the base race with 1, 4 and 12
    Characters, using Rapier's own profiler. The Match server logs its tick
    duration behind a flag.
- **Load only what the Track places**: the already-planned memory-footprint
  tickets 01 and 02, done inside this milestone and not rewritten.
- **Draw less for free**: `camera.far` follows the preset's `fog.far` (plus a
  small margin). Everything past it is already solid fog colour.
- **Graphics quality** (ADR 0079): `high` (today, default), `medium`, `low`.
  The player picks it in Settings → VIDEO. It is stored per device and applied
  when the Stage is built.
- **No first-sight hitches**: compile the Stage's shaders and upload its
  textures once it is built, before the Round runs.
- **Decide physics from numbers**: if the benchmark shows `world.step()` or the
  per-tick Moving Segment switching as a real share of the tick, distance
  activation becomes its own design (an ADR, since it touches the shared-step
  invariant). If not, it is closed as not needed.

## Not in this milestone

- **Declined by the user (2026-09-17):**
  - a lighter `trap_trapball` visual (glTF-Transform `simplify`),
  - making small pieces (flags, signage, spring pads) non-casting.
- **Declined by the user (2026-09-17):** an automatic quality downgrade
  (ADR 0079).
- **Only if the numbers ask for it (decided in ticket 07):**
  - distance activation of Moving Segments,
  - a `BatchedMesh` for still KayKit Segments,
  - camera and floor raycasts through Rapier `castRay`.
- **Not recommended by the research:**
  - culling still colliders by distance,
  - streaming visuals ahead of the player,
  - meshopt/quantized collision.
- **The builder's own memory work** (memory-footprint 03/04), Lobbies sharing
  one library (06), and the Docker image (07).
