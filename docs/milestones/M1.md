# M1 — Local physics playground

## Done when

> **"It's fun to walk, jump, bump, and fall."**

If after 30 minutes of playing it ourselves we're happy just shoving the
Character off a ledge, M1 succeeded — that's the core gameplay loop.

## Scope

Single-player. No multiplayer, no server, no lobby, no accounts, no backend.
But: fixed 30 Hz simulation with a render-interpolation layer from day one (ADR 0004).

## Checklist

### Character & control
- [x] One kinematic capsule Character
- [x] WASD movement (relative to movement/camera per Q12: dash impulse follows movement direction, not camera)
- [x] Jump — variable height (hold = higher), coyote time ~100 ms, **no double jump**
- [x] Dash — ground only, cooldown ~1 s, fixed impulse in movement direction
- [x] Dash into a wall/edge → transition to Ragdoll
- [x] Procedural `Wobble` on the visual mesh while `Controlled` (cosmetic, no collision effect)

### Character state machine (ADR 0006)
- [x] `Controlled → Stagger` on minor Impact; auto-recovers
- [x] `Controlled → Ragdoll` on hard Impact / Fall / dash-into-wall
- [x] Short `Ragdoll` with real articulated physics
- [x] `Ragdoll → GettingUp` blend back to standing
- [x] `GettingUp → Controlled`
- [x] Impact Reactions visible (flinch / knockdown)

### World
- [x] Basic platform geometry
- [x] An edge you can walk / be knocked off → `Fall` below a kill-plane
- [x] Checkpoint + Respawn with a short time penalty
- [x] One Spinner (rotating Obstacle bar)
- [x] A few simple dynamic physics props to bump into and knock around

### Camera
- [x] Third-person spring-arm follow
- [x] Camera collision (shorten the arm against geometry)
- [x] Optional mouse orbit, mostly-fixed pitch

### Engine plumbing
- [x] Fixed 30 Hz simulation step, living in `packages/shared`
- [x] Render loop at display refresh rate, interpolating between sim states
- [x] Tuning constants (jump, dash, fall threshold, penalties) as named constants in `packages/shared`

## Explicitly NOT in M1
Multiplayer · server · lobby · accounts · procedural Segments · Modules ·
Rounds · Qualification · Power-ups · Item Boxes · Grab · Betting · level themes.

## Ticket 07 — feel-tuning pass (final values & verdict)

**Wobble:** `apps/client/src/wobble.ts` — a pure, unit-tested `stepWobble`
function (inertial lean: accelerating throws the lean backward, a hard stop
throws it forward, settles to upright at a constant velocity or standing
still). Wired into the render loop through a `wobblePivot` node between the
Character's placement group and the model, so the lean is always relative to
the Character's current facing. `Controlled` only, per ADR 0006; resets
cleanly on every Ragdoll/GettingUp/Controlled transition. Cosmetic tuning
constants live locally in `wobble.ts` (`WOBBLE_ACCEL_SCALE`, `WOBBLE_MAX_TILT`,
`WOBBLE_SETTLE_RATE`), matching how camera feel already lives in
`camera/springArm.ts` rather than the shared package — Wobble never reads or
writes simulation state.

**Tuning constants reviewed against real play, changed:**
- `DASH_COOLDOWN_MS`: 1000 → **1500**. Session-live playtesting had pushed
  `DASH_SPEED` to 15 and `DASH_DURATION_MS` to 1000 (a slower, more sustained
  dash than the original 22 u/s / 230 ms burst) — but that left the cooldown
  *equal to* the duration, which mathematically cancels the rest period
  (`DashController`'s cooldown and duration timers start together and tick
  down in lockstep, so cooldown always hits zero the instant the burst ends).
  Raised the cooldown so a real ~500 ms rest follows every dash. `DASH_SPEED`
  and `DASH_DURATION_MS` themselves are left at this session's tuned values.
- `PLAYGROUND_SPINNERS[0].angularSpeed` (`apps/client/src/playground.ts`, not
  a shared tuning constant — this is level content): 2.5 → **6.5** rad/s. At
  2.5, even a hit at the very tip of the bar (armLength 2.5) landed at impulse
  magnitude ≈ 4.25 — under `IMPACT_RAGDOLL_MIN` (9), so the Spinner could only
  ever Stagger, never knock down. At 6.5 a tip hit lands ≈ 10, a real
  knockdown, while a graze nearer the axle still only Staggers.

**Everything else** (walk speed, jump arc, coyote time, capsule size, Impact
thresholds, Ragdoll/GettingUp timings, Fall penalty, dash-into-wall and Prop
push tuning) was reviewed and left as tickets 02–06 set it — nothing else
stood out as broken against play.

**Playtest verdict:** this was an automated smoke-playtest (headless-browser
sessions driving every mechanic — walk, jump, dash, the Spinner, Props, a
Fall/Respawn cycle, Ragdoll→GettingUp) verifying nothing is broken and the
numbers above needed changing, not a substitute for the human 30-minute
self-playtest this milestone's "done when" calls for. One finding worth a
human's attention: the current dash (peak 15 u/s over ~1 s, so up to ~11 units
of actual travel) covers most of the M1 scaffold track's individual platforms
in a single burst — nearly any dash on the original track now clips a wall,
the Spinner, or an edge. The open sandbox platform added past the end
platform (`PLAYGROUND_STATICS`, 30×30, flush with the end platform's top) for
this playtest gives room to feel the dash without that. Worth a human pass to
decide whether that's the intended "everything is close together and
dangerous" chaos, or whether the track should grow to match the new dash
range.
