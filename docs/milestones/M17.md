# M17 — Bots

## Done when

> **A host ticks Bots on, starts a Race, and the empty places fill with
> Characters that run the Track, time the obstacles by their difficulty,
> shove, grab and throw whoever is at hand, fall only for a reason, and
> finish.** The same Bots are playable from the menu without a server and
> walk every authored Track in the suites.

## Design

Settled with the user in three question rounds on 2026-09-24, and recorded as
**ADR 0129**. In short:

- A Bot is an input source on the authority (Match server, local practice,
  headless suites), with its code in `packages/shared`. There is no protocol
  change.
- Race first, and Hit, Grab, Spin, Hurl, carry and Bomb are part of it.
  Survival reuses the same parts.
- Bots are chaotic but never step off on their own.
- The host picks EASY / NORMAL / HARD, and every Bot gets a seeded spread
  around it. Seeing moving obstacles coming scales with difficulty.
- Bots target whoever is at hand.
- Bots score and can win, but nothing is persisted for them. They look like
  Players.
- Navigation uses `recast-navigation-js`, with a navmesh from the Track and
  jump links proven in the simulation. Decisions use `mistreevous`.
