# M5 — Two Round types on one engine

## Done when

> **A Match can run a Race or a Survival Round on the same simulation, with the rules that differ
> carried as data — and Survival is genuinely playable: shove the others off, last one standing
> Qualifies.**

The point of this milestone is not the abstraction. It is the **second implementation**, because
that is the only thing that proves the seam is in the right place. An abstraction with one
implementation is a guess, and the project's own rule is not to build for speculative scale — the
same instinct as ADR 0011's "validated at 2, shaped for 12". Survival is built for real, on real
content, verified live.

Design settled in a grilling session backed by two research notes and recorded as **ADR 0041**
(Round configuration: Track defaults, Round overrides), **ADR 0042** (what a Fall does is the Round
type's rule) and **ADR 0043** (a Round type is data in the shared step, never a branch on the mode).

**Why Survival and not the collapsing floor:** Survival forces the exact question the architecture
exists to answer — can a Round type override a rule the shared deterministic step currently
hardcodes? — while needing **no new content systems**. A collapsing floor is a content problem
wearing a Round-type costume: terrain that changes mid-Round must be a pure function of the Tick in
shared code (the `Spinner` pattern, ADR 0025), and that deserves its own milestone once the seam
exists.

**The encouraging finding:** the audit found the Race assumptions are not scattered. They sit in
about six places, four of them inside the shared deterministic step. And M4's design already fits —
`allQualified` takes any `{finishTick}` record and `finishTick` is a Tick rather than a boolean, so
**Survival needs no wire change** to Qualification.

**What M5 inherits from M4.5:** the server is split by concern before this milestone starts
(M4.5 ticket 09), so M5's server-side work lands in `matchLoop.ts` and `lobby.ts` rather than in an
846-line `index.ts`. The modules exist; M5 changes what is inside two of them.

## Checklist

### The seam
- [x] One rule for "this Character's input is locked", replacing the two mechanisms at two layers
      that exist today — Qualification's lock inside the shared step and the phase lock outside it.
      Every Round type that changes who may move lands on this fork, so it is unified first
      (ticket 01, ADR 0044)
- [x] `RoundRules` — a shared data record the step reads *fields* of, never a Round-type name.
      Resolved once before COUNTDOWN from the Track's defaults under the Round's overrides
      (ADR 0041), and replicated on the snapshot beside `phase` (ADR 0043) (ticket 02)
- [x] A Round with Race rules resolves to exactly today's behaviour, pinned by the existing tests
      (ticket 02)

### Survival
- [x] What follows a Fall is a rule, not a constant: a Race respawns at the last Checkpoint,
      Survival eliminates (ADR 0042) (ticket 03)
- [x] An eliminated Character is **marked, not removed** — its entry stays in the collection and
      its body stays in the world with its collider disabled, so the simulated set and the
      iteration order never vary. It is not stepped. The M4 ticket 05 disconnect path, which
      removes a Character mid-Round today, is fixed with it (ticket 04)
- [x] A Survival Round ends when the Survivor Target is reached or the Time Limit expires —
      whichever first — and everyone still standing Qualifies (ticket 05)
- [x] An arena Module: one flat platform over a void. Deliberately minimal — the shoving is Bump,
      which has worked since M2; what makes it a Survival Track is only that it has edges (ticket 06)

### Authoring and choosing
- [x] The Track builder authors a Track's default Survivor Target, exactly as it authors the
      Time Limit (ticket 07)
- [x] The Lobby picks the Round type, and the server refuses to start a Round whose Track cannot
      support it — a Race needs a Finish Zone. Validated at Round start; Tracks are never tagged
      with the Round types they allow (ADR 0041) (ticket 07)

### Verification
- [x] Live with two browsers, both Round types on the same server: a Race that still plays exactly
      as it did in M4, then a Survival Round where one Player shoves the other off and Qualifies as
      the last one standing, then a Survival Round that ends on the clock instead (ticket 08).
      Found three real bugs vitest had not — ghost Characters left behind by the last Player to drop
      mid-Round, a Track pick freezing everyone already in the Lobby by restarting the Tick epoch
      under their already-seeded prediction tick, and a DNF'd Player listed twice on the Results

## Explicitly NOT in M5

Multi-Round advancement and Qualification carry-over (next, once two Round types exist to chain) ·
collapsing or otherwise changing terrain · Collect and Team Round types · new mechanics such as
Hit or Grab · scoring across Rounds · Skyfall · generator support for arenas.
